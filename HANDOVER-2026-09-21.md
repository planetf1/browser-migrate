## 3. Key technical findings (the hard-won stuff)

### macOS 27.0 (build 26A428) Safari — day-one, released 2026-09-21
- **Import bug after profile delete/recreate**: Safari's
  BrowserDataImportingService resolves the target profile from stale state
  (refs linger in SafariTabs.db) and targets a *phantom* profile directory.
  Imports "succeed" into the phantom (not visible in Profiles UI); user's real
  profile stays empty. If the phantom dir is deleted, import fails outright:
  `WBSHistoryErrorDomain Code=3 "Failed to connect tp history database"`
  (yes, "tp" — Apple's typo, in their log) + `XPC connection was invalidated;
  falling back to in-process history database`. WBSHistory* is Apple-internal
  (NOT in open WebKit — verified by blobless clone of WebKit main).
- **Workaround that worked**: write directly to the profile's History.db with
  Safari quit (direct_import_safari.py). Same row shapes Safari's importer
  writes, plus generation stamping (below). Verified: history rendered in UI.
- **90-day import cap** (public, github.com/yigegongjiang/export-chromium-history):
  Safari only ingests last 90 days of imported history. Work export (Jun 23→Sep 21
  = exactly 90 days) fit; older Edge history would be silently truncated by the
  UI import but NOT by direct-DB writes.
- Import dialog counts **"sites" (unique domains), not entries** — "155 history
  sites" for a 4,078-entry file.

### New Safari History.db schema (macOS 26/27; not in open WebKit)
```
history_items(id, url UNIQUE, domain_expansion, visit_count,
              daily_visit_counts BLOB, weekly_visit_counts, autocomplete_triggers,
              should_recompute_derived_visit_counts, visit_count_score, status_code)
history_visits(id, history_item FK, visit_time REAL  -- Cocoa seconds (2001-01-01),
              title, load_successful, http_non_get, synthesized,
              redirect_source, redirect_destination, origin, generation,
              attributes, score)
history_tombstones(id, start_time, end_time, url NULL=whole-range, generation)
metadata(key,value): current_generation, last_synced_generation,
              sync_with_manatee_container (Manatee = history sync engine),
              profile_server_map, profile_server_identifiers, ...
```
- `generation`: sync-generation counter. **Stamp imported rows with
  `last_synced_generation`** → treated as already-synced, no iCloud upload.
  (default profile: 126; work profile: 2.)
- `domain_expansion` = host minus public suffix: login.intranet.example→login.intranet.example,
  bbc.co.uk→bbc; NULL for IPs/special schemes. (Search engines: google/bing.)
- `daily_visit_counts` blob = u32le per-day visit *scores* (1 visit→20 or 100;
  seen 20,25,40,60,100), anchored at most-recent visit day, short window.
  Imported single-visit rows carry [100] — **identical shape to native rows**,
  so the blob was a red herring for the visibility bug; generation was the fix.
- Tombstones with url NULL + sentinel start_time = "clear all history"; they
  suppressed re-imports of just-cleared URLs (the 17:2x import/clear loop).
- History is per-profile; **bookmarks are shared** (one plist, CloudKit-synced;
  Safari rewrites the plist while running → all plist edits need Safari quit).

### TCC / permissions
- Reading Edge/Safari data dirs needs **Full Disk Access for Ghostty** (the
  terminal = responsible process). `sudo` does NOT bypass TCC (verified: same
  EPERM as root). User has granted it (Ghostty FDA working this session).
- `log` is shadowed by a user shell function → use `/usr/bin/log show`.
- Safari's profile names are NOT in the profile dirs; profile identity has to
  be inferred from content/extensions (or a probe visit).

### Edge (Chromium) side
- **Directory names ≠ display names**: `profile.name`/`account_info` in
  Preferences are the UI names; dir names are creation-order identifiers.
  User's Edge Beta: dir "Default" = UI "Profile 1" (personal nigel@cherrybyte.me.uk),
  dir "Profile 1" = UI "Profile 2" (work work@example.com), dir "Profile 2" =
  dormant UI "Profile 3". (This caused the original misnamed output files.)
- Edge history = last ~90 days only in this case (Jun 23→Sep 21 work;
  May 18→Sep 21 personal). Per-URL export: urls.last_visit_time,
  epoch 1601, minus 11644473600×10⁶ µs.
- Bookmarks JSON roots: bookmark_bar/other/synced; HTML export = Netscape
  format; Safari imports HTML bookmarks into the shared store, merging into
  same-named folders (work+personal "Favourites Bar" got merged — hence the
  content-based reorg that followed).
- Bookmark plist: WebBookmarkTypeList/Leaf, leaf title in
  URIDictionary.title (NOT "Title"), leaves have WebBookmarkUUID + URLString +
  dateAdded. Repeated HTML imports create URL-duplicates (486 found) incl.
  mojibake variants (UTF-8-read-as-Latin1: "â€" / "Â" markers; fix =
  t.encode('latin-1'|'cp1252').decode('utf-8')).
